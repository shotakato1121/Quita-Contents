# AZ-104 学習ログ Day3：境界設計と可用性・観測性の考え方

## はじめに
この回では、Azure 機能の暗記ではなく「なぜその境界にするのか」を基準に整理する。

### これまでに学習した内容
- Subscription / Resource Group / Region / Resource の役割
- Management Group と RBAC スコープ設計

## 本文
### ネットワーク境界（VNet / Subnet / NSG）
VNet は IP 空間の分離だけでなく、障害影響範囲を制御する境界になる。Subnet は責務と制御を分離する単位で、NSG は通信を許可/拒否する実行時の制御。

### 可用性設計（RTO / RPO）
可用性設計は、先に RTO / RPO を決めるのが基本。

- RTO：復旧までに許容される時間
- RPO：損失してよいデータ量

この2つを決めてから、可用性セット・ゾーン・リージョン冗長などの手段を選ぶ。

### 観測性（メトリクス / ログ / 相関ID）
運用で必要なのは「検知」だけでなく「追跡可能性」。

- メトリクス：異常の兆候を数値で見る
- ログ：原因の詳細を掘る
- 相関ID：リクエストを境界越しに追跡する

相関IDがないと、原因調査に時間がかかりやすい。

## まとめ
- 境界はネットワーク分離だけでなく影響範囲制御のために設計する
- 可用性は SLA 参照より先に RTO / RPO で決める
- 観測性はメトリクス・ログ・相関IDを組み合わせて機能する
