コードを読みやすくするうえで、特に差が出やすいのが「名前の付け方」だと感じました。

今回は、変数名・関数名・クラス名とメソッド名を付けるときに意識したい基本をまとめます。

## 命名で大切なこと

名前は、見た瞬間に「何が入っているのか」「何をするのか」が伝わることが大切です。

- 意味のない名前は使わない
- 役割や中身がわかる名前にする
- あいまいな表現を避ける
- 短すぎず、長すぎない名前にする

短い名前が必ずしも良いわけではなく、読み手が迷わないことのほうが重要です。

## 変数名

変数名は、保持している値が伝わる名前にします。

- 悪い例: `a`
- 良い例: `userCount`, `totalPrice`, `createdAt`

`a` のような名前では、何が入っているのかがわかりません。
一方で、値の意味がわかる名前なら、コードの流れも追いやすくなります。

## 関数名

関数名は「何をしているか」だけでなく、「何に対して何をするのか」まで伝わるとわかりやすくなります。

- 関数の中身を見なくても役割が想像できる名前にする
- 抽象的すぎる名前を避ける
- 動詞から始めると意図が伝わりやすい

例えば `process()` や `handle()` のような名前は便利に見えますが、処理内容が広すぎて伝わりにくいことがあります。

## クラス名とメソッド名

クラスの中のメソッドも、クラス名と組み合わせたときに意味が自然に伝わることが大切です。

- 悪い例: `divide`, `multiply`
- 良い例: `convertMinutesToHours`, `convertMinutesToSeconds`

```js
class TimeConverter {
  convertMinutesToHours(minutes) {
    return minutes / 60;
  }

  convertMinutesToSeconds(minutes) {
    return minutes * 60;
  }
}
```

このように名前だけで処理内容が想像できると、メソッドの中身を毎回確認しなくて済みます。

## まとめ

- 名前だけで役割がわかるようにする
- 省略しすぎない
- あいまいな名前を避ける
- 読む人が迷わない名前を選ぶ

命名は小さなことに見えて、コード全体の読みやすさを大きく左右します。
まずは「この名前で初見の人に伝わるか」を意識するところから始めたいです。
